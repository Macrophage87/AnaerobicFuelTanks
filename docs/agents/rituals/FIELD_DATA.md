# Ritual: ingesting field data from a FIT

Read this **when a recording is about to become evidence** — when a `.fit`
from a real ride is going to justify a number, a threshold, a default or a
display decision.

Facts and commands: `docs/agents/FACTS.md`.

---

## 1. The rule

**A recording is not evidence until something committed can regenerate every
figure taken from it.**

This repository has already taken figures from recordings that nothing
committed can regenerate:

* **#100**: the lag table (corr 0.599 / 0.738 / 0.822 / 0.680 at lags −1…+2)
  and the threshold fit came from a saved FIT of the 2026-07-26 ride, decoded
  outside the tree.
* **#92**: "the 2026-07-20 ride showed a PCr-heavier split near fP≈0.55" — a
  fit result with no committed input.
* **#96**: "four co-installed CIQ apps wrote 53 B of developer payload to
  RECORD" — the observation that settled the per-app budget question, from a
  file that is not here.

Each is probably right. None can be checked, re-run under a changed model, or
distinguished from a decoder-lap-boundary error by anyone who was not there.

No `.fit` file is committed to this repository (`git ls-files` matches none),
and that stays true. What is committed is a **text fixture plus its
provenance**, so a reader with any FIT decoder can rebuild it from the original.

## 2. Where fixtures live, and what exists today

`tools/crosscheck/fixtures/` holds **synthetic** traces generated by
`gen_fixtures.R` (`sprint`, `supra`, `interval`, `aer_excess`) with their
config CSVs; `tools/calibrate/tests/testthat/fixtures/` holds the R suite's
simulated rides. **No fixture derived from a real recording exists.** The
first one should follow the shape below and get its own reader script, so that
#100's lag and #92's split become numbers a CI job prints.

One series per file unless the question **is** the relationship between series
at the same second — then one file, every series on its own named line, read by
name never by position, and the loader **refuses** mismatched lengths.

## 3. The provenance block is not optional

Every fixture header carries enough to reproduce it from the original with any
FIT decoder:

```
# PROVENANCE, so this is reproducible from the original with any FIT decoder:
#   source file    <activity id or filename>, recorded <date>, device <part number / firmware>
#   values         the 'PCr_J' DEVELOPER FIELD of record messages (FIT global message 20),
#                  developer_data_index N, field_definition_number 0, in timestamp order;
#                  native 'power' (field 7) beside it
#   window         session start_time (field 2) inclusive to timestamp (field 253) exclusive
#   selection      every record carrying a native power value -> 875 records, 951 s
#   precision      float32 in the file, written here to 1 decimal place
#   absence        a record with no native power is written as NA, not 0 (0 W is a real reading)
```

Every line is load-bearing: the message and field numbers, not just the name;
the boundary convention; the selection rule with its resulting counts, so a
reader knows immediately whether they reproduced the same set; the precision
tied to the decision it must not perturb.

## 4. State the absence encoding, always

**Absence must be a distinct state, and which state it is must be written down
before anyone needs it.** Absence rendered as a value is a named defect class
here (`FACTS.md` §6, #76): a missing power reading shown as 0 W recovers the
tanks; a missing reserve shown as 0 J empties them.

Record-scope developer fields **latch** (`FACTS.md` §3.3): a flat run of
identical values in a recording may be a real steady state **or** a skipped
write re-emitting. The recording alone cannot distinguish them; the fixture
header must say which the app's write policy makes it.

## 5. Publish a range, not a point, until the definition is pinned

A single number with no stated definition is not a measurement. #100's peak at
lag +1 is one definition (Pearson on the combined draw); the threshold fit is a
second, and they agree — which is what makes the finding strong. Write both
down, and the sweep of definitions that were tried, in the script that prints
them.

## 6. Cross-checks a reader can run in two minutes

Every fixture header ends with them: per-window medians, the peak and where it
sits, the record count. Without them, "I could not reproduce your number" and
"I decoded a different window" are indistinguishable.

## 7. What field data cannot settle

* **Nothing in this repository decodes a file this app wrote** (`FACTS.md`
  §3.2). A recording tells you what a *decoder* read out of a file some
  firmware wrote; it does not tell you what *this app's* `setData` calls
  produced.
* **The per-app budget claim** (#96) rests on one file with four apps. The
  maintainer reports memory failures with several data fields installed
  (2026-09-05). Both are field observations; neither is a fixture yet. The
  question they leave open — what fails, in which app, at what total developer
  payload — is a `[Local]` measurement with byte-exact criteria, not a design
  argument.
* Anything needing a real device or a real ride gets a `[Local]` issue:
  `[Local]` title prefix, opening ⚠️ blockquote, `local-test` label (create it
  first, `FACTS.md` §3.4), byte-exact pass criteria.

## 8. Retract at the quotation site, not just in the analysis

When a published figure turns out to be wrong, the retraction goes **both**
places: in the harness that now prints the correct one, and at every comment
that quoted the old one, naming the old figure. #96's body is the house style
for the second half.

## Mid-work hazards

* **Never `git add .` / `-A` / `commit -a`** (`FACTS.md` §4.2).
* **`set -o pipefail`** for anything whose result you quote (`FACTS.md` §2.6).
* Fixtures are text and land in the tree under `core.autocrlf=true`
  (`FACTS.md` §4.1) — check what a consumer does with line endings before
  trusting a local run. `tools/calibrate/.gitattributes` is the one place that
  already pins them.
